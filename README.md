# dsh-agent-soul-kit

**版本 1.0.0** · MIT · macOS / Windows / Linux

给 Agent 用的作业指导书与取证工具包。它本身不替你装东西——它把「作者上游现在长什么样、你这台机器现在是什么状态」变成结构化事实，让 Agent 按你的选择现场生成这一次要执行的脚本。

## 为什么不是一键安装

上游会变：新增零件、改包名、调安装流程。任何写死这些决定的安装器，迟早和上游对不上，而且对不上的时候你只会看到一句报错。

所以这里的分工是：

| 谁 | 干什么 |
|---|---|
| 指导书（playbooks） | 说清该看什么、怎么判成功、失败长什么样 |
| 取证脚本（probe） | 只读：把上游结构、本机状态、差异、日志变成 JSON |
| Agent | 读上面两样，生成这一次的安装 / 更新脚本，干跑给你看，你点头再真跑 |
| 你 | 选装什么、叫什么名字、要不要打补丁 |

生成的脚本留在本机，不进仓库。

## 交给 Agent 开始

把本目录放到一个固定位置，让能读写本机文件的 Agent 以它为工作区，然后说：

> 读这个目录的 AGENTS.md，然后按 playbooks/install.md 帮我把 dsh-agent-soul 装到这台电脑上。每一步先跟我确认。

更新同理，把 `install.md` 换成 `update.md`。

## 目录

| 路径 | 是什么 |
|---|---|
| `AGENTS.md` | 给 Agent 的边界与红线 |
| `playbooks/` | 安装、更新、备份还原、诊断的判据与验收 |
| `probe/` | 只读取证脚本 |
| `kit/` | 会写东西的那一层：补丁引擎、备份还原、诊断渲染、导出报告 |
| `docs/` | 架构设计（给维护者看） |
| `data/` | 本机运行数据，不进 Git |

## 三件不做的事

1. **不改上游。** `upstream/` 或 `--source` 指定的目录是只读来源。
2. **不替你做决定。** 装哪些零件、用什么名字，都是问出来的。
3. **不自动提交。** 本工具不 `git commit`、不 `git push`。

## 数据放哪

    data/
    ├── <profile>/<instance>/apply/    # 你的选择、生成的脚本、干跑报告
    └── _kit/                          # 补丁库、运行记录

整个 `data/` 被 `.gitignore` 排除。移动或删除本目录前先想清楚——里面是你这台机器的安装依据。
